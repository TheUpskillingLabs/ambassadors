# Ambassador Guide

A mobile-first site that gets Upskilling Labs ambassadors ready to represent The Labs. The idea behind every screen: **think of someone who's figuring out what's next.** The site keeps offering that prompt, then gives the ambassador the words and the nerve. The ladder is four verbs: **Raise your hand → Get in → Get ready → Pass it on.** Getting in takes ten minutes on a phone (`/apply/`) and ends with the coordinator handing over the button in person. Getting ready is the guide: one path of five steps, one page each, **The Labs → The Conversation → Your Story → The Room → Practice**. Passing it on earns the pin. There's also a boilerplate deck you can present from `/present`.

It uses the same design system as OLOS: the brand tokens, type scale, buttons, cards, and ink chrome are ported from `OLOS/app/globals.css`.

**Status:** v1 prototype. All copy is seed copy marked `[PLACEHOLDER]` until real Labs copy replaces it (see [Replacing placeholder copy](#replacing-placeholder-copy)).

## Stack

- [Astro](https://astro.build) static site with content collections (Markdown + JSON, validated by schemas in `src/content.config.ts`). There's no backend and no database.
- Geologica, self-hosted via `@fontsource-variable/geologica` (OFL).
- QR codes are generated in the browser with `qrcode-generator`.
- A service worker (`dist/sw.js`, generated at build) precaches every page, so the site works offline after the first visit. It can be installed as a PWA.
- Deploys to **GitHub Pages** via `.github/workflows/deploy-pages.yml` on every push to `main`. PRs build and type-check but don't deploy. For this to work, **Settings → Pages → Build and deployment → Source** must be set to **GitHub Actions**. The "Deploy from a branch" option runs Jekyll on the raw repo and fails.
- The site works at any base path. The workflow passes the Pages path (`/ambassadors` on `theupskillinglabs.github.io`, or `/` on a custom domain) as `BASE_PATH`. Every internal link goes through `u()` in `src/lib/url.ts`, so new links in components should use it too. A root deploy (Vercel via `vercel.json`, or a custom domain) needs no configuration.

```sh
nvm use            # Node 22.12+
npm install
npm run dev        # http://localhost:4321
npm run build      # checks copy, builds dist/, writes sw.js
npm run preview    # serve dist/ (the service worker only runs in a production build)
npm run check      # type-check
```

## Common edits (no developer needed)

You can make all of these in GitHub's web editor. Open the file, click the pencil icon, and commit. The site redeploys within a couple of minutes.

- **A step's copy:** edit its file in `content/steps/`. It's plain Markdown. To place a built-in block, put one of these on its own line: `<!-- ladder -->`, `<!-- faq -->`, `<!-- story -->` (the reader's saved 30-second why), `<!-- asks -->` (Who will you ask?), or `<!-- present -->` (the deck buttons). A misspelled name fails the build and names the file.
- **Next session:** add an entry to `data/schedule.json`. The deck (slides 5 and 6) and the invite text pick up the next future session automatically, and past sessions drop off on their own.
- **A practice situation:** copy any file in `content/scenarios/` and give it a new `id` and filename. `"core": true` puts it in the first round, which should stay at 6.

Every build validates the files against the schemas in `src/content.config.ts`. `npm run lint:copy` also runs on every build. It flags the brand's banned words (course, class, student, lesson, module), "TUL", exclamation points, emoji, "civic problems", and "Sign up / Get started".

## Replacing placeholder copy

Every seeded entry has `"placeholder": true` (or `placeholder: true` in the Markdown frontmatter). While the flag is set, the page shows a `[PLACEHOLDER] draft copy` marker. When you replace an entry with real copy, set the flag to `false` and the marker disappears. To find what's left:

```sh
grep -rl "placeholder: true\|\"placeholder\": true" content/
```

These also need real values:

- `content/site/help.json`: the coordinator's name and email (currently `coordinator@example.org`).
- `data/schedule.json`: real dates and places.
- `content/site/story.json`: example stories from real people, with their permission and credit.

## Design rules

The site follows The Labs Brand Style Guide via the OLOS design system. Some rules are easy to break by accident:

- **The logo always sits on ink.** The program page header has no bar: a soft pool of ink behind the logo fades out across it. The guide's bar is solid ink.
- **Sentence case, with one deliberate exception.** The brand kit says no all-caps on the website. The program page's hero sets "Ambassador Program" in caps on purpose: it is treated as a product wordmark, the way a launch page sets a product name, and the 12px kickers follow the OLOS label style. Everything else is sentence case.
- **Never let anything look like a button unless it is one.** Filled or outlined rounded boxes (`.btn`, `.chip`, `.ctl`) are only for things you can press. Labels, statuses, counters, page lists, and example quotes are plain text or text with a rule, never boxed. On slides, "Join The Labs" is words over a red rule, because nobody can press a projected slide.
- **Full width.** Pages run edge to edge with one fluid gutter (`--gutter: clamp(16px, 4vw, 64px)`); text keeps a readable measure (`--measure: 68ch`) and sits left-aligned. On wide screens the steps become a sticky rail and Home splits into two columns. See `design/research/award-benchmarks.md` for the references behind this.
- **One path, one button.** Every step is one page with one primary action (Done). Anything that adds a second path, a second menu, or a choice the ambassador has to make before they can start should earn its place with evidence.
- Clickable rows are white cards with a trailing chevron (`Row.astro`). Information panels are tinted (`.panel`) or plain text, never white boxes, so anything that looks like a card can be pressed.
- Every gesture has a button and a key. The practice deck supports swipe, buttons, and keys (Space flips, → Had it, ← Not yet).
- Keep copy as short as it can be. One idea per line, no helper text where a title is enough.
- One 14px radius, no pills. Circles are only for controls that really are round (the deck's action buttons). Red is only for "Join The Labs". Teal is for focus rings and accents; use teal-deep for text on light backgrounds.
- The white logo lockup goes only on dark surfaces.

## The visual language

The home page's live model, the orbit emblem, the weave and the pins are one system. The idea: The Labs is a solar system you can join, a complex adaptive system round one orb, made of the same materials as its pins. Each element has one meaning, wherever it appears.

- **The ground is ink** (`#00141B`). Light comes only from the glows (teal above, red below, as in the logo), with the grain only in the light, and from sparks.
- **The orb is The Labs:** the logo's orb, with its three latitude bands. It's the deepest well, and it's always the way in (Join The Labs).
- **No one owns a Lab.** The Labs isn't any person's, and neither is any Lab: the copy never says "your Lab", "their own Lab" or "yours" of a Lab or of The Labs. People start a Lab, join one, run one, have a seat at the table; a Lab is the one near you, or a city's. (Possessives are fine for what people make, their names, teams and Pods.)
- **Gold is the norm; silver is the national org's.** Everyone comes in at the local level: the central platform (the account) directs them to the Lab near them, their regional association. So the metal people see is gold, the regional metal (as on the pins and cockades): the Labs' orbits, knowledge, the glyphs' rims, Share (`--metal` in `src/styles/home.css`; the gold values in `src/scripts/orbnet.ts`). Silver means the national org, and in explainer visuals the national org is always silver: the commons round the orb (its dust, its knowledge, the contributors and the ties into it), the orb's wave, and the official versions it sends out to every Lab (`--national`, and `NATIONAL` in the shaders). People discover what silver means later; the page never explains it.
- **Orbits are paths.** In the live model they're gold dust, bending into the wells of dense Labs, and silver only round the centre, where the commons is. A swoosh (the logo's chevron, a craft in orbit) flies a path.
- **One set of glyphs** (`.gem` and `.mk` in `src/styles/home.css`; the same shapes in `src/scripts/orbnet.ts`):

  | Glyph | Actor in the model | Path | Colour (on the page / as light) | Material |

  | pearl dot | people | (the people on every path) | `#FFDBBD` | pearl |
  | teal square | places | **Learn** | `#00A8B8` / `#24D6DB` | teal candy enamel |
  | red diamond | projects | **Build** | `#ED1920` / `#FF5C47` | red candy enamel |

- **The paths in motion.** Sparks follow the cycle: red out along a project's ties (build), teal up through a contributor to the orb (what was learned), then silver back out to every Lab (the national org's official version), where it spreads again. The wave from the orb is silver.
- **The weave: the orbits drawn out through time** (`STRAND_VS` in `src/scripts/orbnet.ts`). An orbit carried on through time is a helix, and that's how the weave is made. The three paths are three of the system's own orbits, neighbours round the orb in its plane, in the same gold dust as every other Lab's orbit (beside "Whoever you are, you're in the right place." they glow faintly in their colours). As the journey moves on they're drawn down out of the plane, their turns tight where they leave their orbits and even below, their radius narrowing, so they drain from the system into a vortex beneath the orb and wind round one another as one triple helix, turning as orbits turn. The camera travels down it: in each path's scene that path's strand draws in to a single thread near the axis while the other two widen into faint loose turns round it; Share's thread runs from teal (what was learned) to gold (given). It never retracts, and the camera never climbs back: the helix carries on down and opens out round the same system one cycle on, drawn `SPOOL` (70) below the first, where the three paths coil into its orbits, lit in their colours (the last twelfth of each path is that orbit, twice round, so it's whole). At the close they pour down into those orbits, and from there become the logo. It's all in the world, through its camera, so it has the same grain, bloom and glow as everything else; on a portrait screen the drawn-out helix fades below the middle, where the words are. The paths aren't steps: use the weave only to stand for them, never as ornament. **Stories on the threads**, told with the model's own glyphs round the camera's place on the helix: open workshops (gold rings) coming down Learn's thread into a ring of people who light up as each passes; on Build's, strangers drifting in to become a Pod round a problem situation (a red glow), then teams round their projects (red diamonds) with Mentors (gold-rimmed) beside them, a knot in the thread that a Mentor's workshop comes down to and frees before rising up the thread, and the projects lighting up at the Showcase; on Share's, contributions (teal, red, gold) flowing down it into the next system's centre, where the orb flares and the official version goes out to every Lab in silver: what the Labs give, gold, comes back from the national org as silver. **At the very end the paths become the logo:** the rest of the system fades, and every grain of the three paths flies to a point of the swoosh (sampled from the brand kit's `orb-mark.png`, denser where it's brighter), laid over the orb as in the mark, in its teal and with the world's grain; then it settles into the exact logo: the page lays the brand's own lockup over the world's orb (its orb at 511.1, 484.3, radius 348.2 in the 2,061-wide source, scaled to the world's), the wordmark fading in as the swoosh forms and the mark taking over as the dust and the orb's halo let go.
- **You** (in `draw()`, `src/scripts/orbnet.ts`). One grain of light is the reader, the journey's one protagonist, warm white with a soft light round it and a short trail that shows which way it's going. It comes out of the orb with your first scroll and is in the picture from then on: in front of the system beside "Whoever you are, you're in the right place."; into the weave with the paths; on Learn's thread and in the workshop's ring of people, lighting up with them; drifting into a Pod and onto a team (at the Showcase the camera is close and the others on the teams turn out to be faces, the first cohort's portraits); sending what you made down Share's thread ahead of you; landing in the next system, one cycle on; and the first to arrive at the new Lab, where it stays through the close. At the end it lets go with the rest of the world, into the logo. Where it is at each scene is set in `youAt` (relative to the camera's place, so it's always in view) and followed on the same kind of smooth curve as the camera. Point at it (or tap it) and the card says "This is you" (`model.hover.you` in `content/site/home.json`).
- **The camera comes in close in the weave.** Each shot has a distance (`dist`): 30 over the system, as before (a long lens, nearly flat, so the hero and the exact logo are unchanged), then the camera falls in through the weave (15) to 9 along the threads and 10 over the next system, with a wider lens for the same framing, so what's near passes by large and what's far recedes. On the threads it looks down the weave (24°) as it falls. The lens is never wider than about 90° across or 77° up and down, so a tall phone keeps the camera a little further back. The stories on the threads are laid out facing the camera (`sp()`), so the world's steady turn never swings them edge-on. **The weave's air** (`MOTE_VS`): a faint haze in a wide shell round the helix, and a near field of dust that always surrounds the camera, a little ahead of it, each mote keeping its place in the world so it streams past as you fall, soft and large near the lens (out of focus), faded at the box's edges so its wrap never shows (`MOTE_BOX`); 3,700 points on desktop, 2,100 on phones. Near the lens every grain fades rather than blots. The next system only comes into the picture as you arrive at it, so a tall phone looking down the weave can't see it early under the words.
- **The opening: the page opens on the logo, and ends on it.** From the top of the page, the world first shows the brand's exact lockup over its orb; the wordmark lets go, the mark hands over to its own dust, and the swoosh atomizes into a halo round the orb that settles into the three paths' rings (lit in their colours); then the whole system forms round them and the title comes in. It runs on its own clock (about five seconds), waits for the lockup's artwork, and hurries if you start scrolling. Not with reduced motion, a still, or a page opened partway down. Until it has played there's no poster and no title (`html[data-intro]`), so nothing shows before the logo.
- **The emblem** (for print and social, not on the page). The orb with three orbits crossing over and under each other, a swoosh flying each in its path's material: `LabsPin.blend`, scene "Home Paths" (rendered in gold, the norm).
- **Materials.** Candy enamel (deep colour, a gloss, fine glitter) and polished metal, from `LabsPin.blend`. On the page, glyphs are drawn in CSS with a gloss and a gold rim, so they read as small enamel pins.
- **Interface colour is separate.** Teal for links, kickers and focus, and the Join button's own colour, are the interface. The candy colours mean a path. Don't use a path colour for chrome, or chrome colours for a path.
- **Calm.** One big idea at a time on a slow heartbeat; nothing follows the cursor; no stars or dust that could be mistaken for actors. Regional Labs carry no labels until the structure is announced.
- **Words beside the picture, never over it.** No scrims, panels, dimming or vignettes over the world. Scenes' words are small and supporting, and cross-fade in place; the detail comes after the journey, on the plain ground.
- **Always moving forward.** Every bit of scroll moves the world, so you feel progress; it only slows, subtly, at the moments that matter most (the triad, the centre, the close), and rests at the end, on the logo.
- **Smooth while it scrolls.** On a phone the journey has to feel buttery, so nothing on it is moved by script as the page scrolls (the words' drift is a scroll-linked CSS animation the browser runs itself): each scene's words are a fixed layer that only fades (opacity), the world is sticky and as tall as the screen gets (`lvh`, so a toolbar coming and going never resizes it), and the lockup at the end is part of the world, so it scrolls away with it. The page measures the scenes once (and again on reflow) and never reads layout back while following the scroll; style writes happen only when a value changes. Phones get a lighter world so the GPU keeps an even 60 frames a second (or, if one still can't at its lightest, an even 30: steady beats fast): about 1.4 pixels per CSS pixel (stepping down, never up, as soon as frames start to slip), a bloom built from a quarter-size picture in four levels instead of a half-size one in five, three-segment orbit trails instead of five, and a little less dust; and each scene's words are hidden outright while far off screen, so the phone keeps no layers for them (shown a screen early, so nothing is drawn mid-fade). On a touch screen the camera follows the scroll on a critically damped spring rather than an ease, since a phone reports its scroll in uneven steps and easing toward each step made the camera's speed jump; and a height-only resize (a phone's toolbars coming and going mid-scroll) re-measures nothing, since every height is in svh or lvh. Nothing in the picture twinkles by the screen's pixels: each grain of dust keeps its own brightness as it moves, the orb's grain is pinned to the orb, and the finishing grain holds still (on a phone's coarser pixels, all three read as jitter).

## Hooking the apply flow up to OLOS

**Invites and pre-approval.** Until OLOS exists, the invite link itself is the pre-approval, and `/invite/` is coordinator-only only because its address isn't published. The invite's details sit after `#` in the link, so they never reach the web server. With OLOS: coordinators (and above) create invitations there (OLOS already has admin invitations, `app/api/invitations/route.ts`), `/invite/` goes behind sign-in, and nominations from `/nominate/` become a queue the coordinator approves. `toOlosPayload()` already sends `source: "invited"` and `invite: { invited_by, pre_approved }`.

**The personal link.** The program page says everyone who joins The Labs through you counts. Today the only mechanism is the free-text "Who referred you?" field in OLOS's registration funnel, so the ask messages say "say {me} sent you", and the guide's share button makes an *ambassador* invite link (`/apply/#ref=Name`), which counts new ambassadors, not new Upskillers. For the promise to be literal, OLOS needs to accept a `?ref=` parameter on its join URL and pre-fill "Who referred you?" from it; then the guide's button can share a Labs URL. With sign-in, `/apply/` can also drop "Your name" (Google already has it) and the founding roster can come from OLOS instead of `data/roster.json`.

`src/lib/apply.ts` is the only place that changes. `toOlosPayload()` already maps the application to OLOS's registration fields (`POST /api/registrations/funnel`: `first_name`, `last_name`, `email`, `zip`, `source`, `referred_by`), plus the ambassador parts OLOS doesn't have yet: an agreement with `doc: "ambassador"` and the quiz result. Before launch, OLOS needs:

- an `ambassador` document type in `agreement_acceptances` (its `doc` CHECK allows `participation | guidelines | mentor` today);
- a place to record orientation (quiz score, when passed);
- its Terms of Service §3 updated: it says "The only additional agreement is the Build Cycle agreement", which an Ambassador Agreement would contradict;
- Google sign-in on `/apply/` (OLOS registration requires it). Then the guide can require sign-in instead of the on-device nudge.

## Assets

The home page's world (`src/scripts/orbnet.ts`) is a live model of The Labs, plain WebGL 2, no library, held on screen (sticky) through the journey and scrolled away after it. The Labs as a federated, practice-based research network, drawn the way actor-network theory sees one: people, places, projects and knowledge are all actors (a pearl dot, a teal square, a red diamond, a gold ring: the page's glyphs, see The visual language), and a Lab is nothing but their ties. Local Labs orbit the orb through orbits of gold dust; a commons of contributors and shared knowledge circles it, in silver (the national org's); contributors bridge each Lab to the commons. It behaves like a complex adaptive system: newcomers drift in and are pulled into the Lab with the strongest pull near them, and ideas that spread leave new ties. Gravity is the density of relationships: a dense Lab's actors orbit tighter and faster, it pulls in more newcomers, glows, bends the orbits under it into a deeper well, and past a density closes into a small orb of its own. Innovations are sparks, in the three paths' colours: out along a project's ties (red, build), up through the commons to the orb (teal, what was learned), and, after the orb glows and a silver wave crosses the orbits, back out to every Lab (silver: the national org's official version); the heartbeat is slow on purpose, so one idea can be followed rather than many flashing at once. The orb is the logo's: its three bands are latitude bands round one pole, fitted to `orb-mark.png`, coloured from the mark by latitude. **The camera travels the journey's scenes** (`SHOTS`, anchored by the sections marked `data-scene`, in order), always moving as you scroll so you can feel yourself going forward: on a smooth curve through every shot rather than stopping at each, slowing (never stopping) only at the few pauses kept for emphasis (`PAUSE`: the triad, the centre, the close), and coming to rest only at the end, on the logo. The scenes' words drift up a little as you scroll, too (a scroll-linked CSS animation, run by the browser). **It only ever goes down.** The journey used to be a palindrome (system, weave, threads, weave, system), so its second half rewound the first: the camera climbed some 35 units back up the weave in one scene and the helix pulled back into its orbits. Now nothing is undone: every value the camera follows runs one way for the whole journey (the target down the weave's axis, the view sinking towards the orbits' plane, the picture's roll, and a steady turn of the world, `SPIN`, 150° over the journey, the way its orbits go, with no yaw swings), the framing only zooms out where the dive outweighs it, and past the middle of the weave (out of sight of both) the system is drawn `SPOOL` below, so the camera arrives at it still going down. Measured over the whole journey on desktop, phone and tablet shapes, the camera's height never rises (before: it rose through about a fifth of the scroll) and it moves backward through about 1% of it (before: a quarter to a third, counting pull-backs). The shots: the whole system, wide; the system again, right of the words; close on the centre; along the orbits' plane with the orb high, the weave drawn down out of it; down the weave's axis, a little further for each of a path's scenes, so the system rises out of frame; then on down onto the next system, the camera swinging over its orb as it arrives; its paths coiled into its orbits; every Lab, where a new Lab is born; close on the new Lab; the close; and the logo. **The weave** is drawn in the same renderer (see The visual language). Anything in the system can be asked what it is while the system is the picture: point at an actor (on a touch screen, tap it) and a small card beside it says what it is and what it's doing here, while it lights up with its ties and its Lab steps forward; the words are in `content/site/home.json` (`model.hover`). Nothing follows your cursor. The orb is the hero's button, "Join The Labs": a real link laid exactly over it, its label on the orb's own face, revealed as you point at it or focus it; pressing it sets off the one big pulse before the account opens. One orb at a time: while the world's orb is on screen the header carries the wordmark alone. It's rendered into a high-range buffer with a finishing pass (bloom on true highlights, a gentle shoulder that keeps the brand colours, grain only in the light) and screened over the stage's glows, so the words sit inside its light; the finishing pass paints the stage itself (`stage()`, the same gradients and grain as `.hm-world`), so the browser composites one opaque picture with no blending each frame. On a touch screen nothing over the world uses `backdrop-filter`, and phones get an even 60 frames a second and a lighter render scale. Quality adapts to the typical frame time (a median, so one long frame never changes it); there's a pause button during the journey; reduced motion holds the world still (the camera and the weave still follow the page); no WebGL keeps the poster (`public/join/hub-poster.webp`). To re-render the poster and the share image, open `/?orb=poster` and save the canvas (it's drawn with `preserveDrawingBuffer`).

`npm run covers` makes the portrait crops of the three chapter covers that phones get (`public/join/*-p-900.webp` and `*-p-1400.webp`, from the 1800w files, centred on each cover's `position`). The phone-sized orbits video (`orbits-600.mp4`, `orbits-600.webm`) was encoded with ffmpeg at 600px wide; re-encode it the same way if the source changes.

`npm run assets` regenerates web-sized brand assets from a sibling OLOS checkout (`../OLOS`): the white logo lockup, partner marks, the grayscale community photo, and the app icons. The white lockup only appears on dark surfaces: the app bar and the dark slides.
